## 기여 1 — as-of 누적 피처 분해 **(+146.8)**

**대회 전체에서 단일 변경 최대 이득이었습니다.**

### 문제

주최측이 제공한 `as-of` 컬럼(그 시점까지의 누적 성적)을 그대로 모델에 넣으면
트리는 **수준(level)** 만 봅니다. 그런데 실제로 의미 있는 것은
"평소보다 지금 잘하고 있는가" 같은 **차분**입니다.

### 접근

누적값을 네 성분으로 분해해 명시적 피처로 제공했습니다.

```python
level      = asof_rate                      # 장기 실력
recent_dev = prev5_rate − asof_rate         # 최근 폼 편차   ← 트리가 만들기 어려운 것
volume     = log1p(asof_n)                  # 관측량 = 신뢰도
volatility = |prev1_rate − prev5_rate|      # 변동성
```

관측량을 함께 준 것이 핵심이었습니다 — 모델이 **각 행의 신뢰도를 학습**할 수 있게 됩니다.

### 검증

누출을 의심할 만큼 큰 이득이었기 때문에, 채택 전에
**독립 코드 경로로 재구현**하고 **4개 연도 홀드아웃에서 일관성**을 확인했습니다.

| | 이전 | 이후 |
| :--- | ---: | ---: |
| Public LB | 818.07 | **964.87** |

## 기여 2 — MLP 블렌딩 **(+36.2, 1,000점 최초 돌파)**

### 문제

GBDT 단독으로 성능이 정체됐습니다. 하이퍼파라미터 탐색으로는 더 안 올랐습니다.

### 접근

신경망을 **GBDT를 이기려고** 넣은 것이 아니라, **틀리는 방식이 달라서** 넣었습니다.
블렌드에서 중요한 것은 각 모델의 성능이 아니라 **오차의 방향**입니다.

SimpleMLP 5-seed를 가중 0.32로 결합했습니다.

### 이후 확인한 것

신경망을 **더 넣는 것**은 일관되게 손해였습니다.

| 구성 | LB |
| :--- | ---: |
| MLP 1종 | **1,001.66** |
| + ResNet + Transformer | 1,008 (기준 1,032 대비 −24) |
| + TabNet | 993 (−39) |

원인은 명확합니다 — **신경망끼리는 서로 상관이 높습니다**
(실측 거리 0.005~0.018, 블렌드 이득에 필요한 값 0.029).
두 번째 신경망은 첫 번째와 거의 같은 방향을 가리켜 기여가 0입니다.

## 기여 3 — 3-way 목적함수 앙상블 **(+12.5)**

이진 라벨이지만 **MSE(회귀)로도 학습**했습니다.
평가 지표가 Brier이므로 회귀가 지표와 직결되고,
분류 모델과 **다른 곳에서 틀리므로** 블렌드 멤버로 가치가 있습니다.

최종 가중치 `GBDT분류 0.40 / MLP회귀 0.40 / LGBM회귀 0.20`.

## 기여 4 — 아핀 캘리브레이션 **(+12.9)**

파라미터 2개(`SCALE`, `SHIFT`)뿐이라 과적합 위험이 거의 없고,
**제출 2~3회로 리더보드에서 직접 최적값을 찾을 수 있습니다.**

이 축에서 **외삽이 실패한다**는 것도 확인했습니다.

| 설정 | LB |
| :--- | ---: |
| SCALE 1.10 / SHIFT −0.0045 | **1,016.13** |
| SCALE 1.15 | 1,008.72 (−7.4) |
| SHIFT −0.01 | 988.78 (−27.4) |

좁은 국소 최적점이고 양방향 외삽이 모두 실패했습니다. 이 축은 조기에 닫았습니다.

그 사실이 몇 분 만에 나왔습니다. 이 판정으로 GPU 시간을 아꼈습니다.

## 배운 것 중 가장 큰 하나

**정직한 홀드아웃 분할 통과는 필요조건이지 충분조건이 아닙니다.**

잔차 후처리 모델을 완전 분리 3분할(학습/계수적합/평가)에서 +6.65로 측정해 출하했는데
실전에서 −4.1이었습니다. 사후 진단에서 세 가지가 전부 기각했고,
**전부 출하 전에 볼 수 있었습니다**:

1. 다른 시점에서 재현되지 않음 (−22.35)
2. 계수 부호가 폴드마다 뒤집힘 (+0.070 / −0.041 / −0.140)
3. **시드 하나로 +6.65 → +3.21** — 효과가 시드 잡음 안이었음

원인은 자유도였습니다. 400트리 × 63리프 모델은
"이 데이터의 오차"가 아니라 **"이 기간의 오차"를 외웁니다.**

이후 판정 규율을 바꿨습니다 — **최소 5시드, 양방향 폴드 부호 확인,
출하할 바로 그 산출물을 검증**(창을 밀거나 재학습했으면 그건 새 후보).

## 기여 6 — 팀 기법 독립 검증과 확장 축 판정

팀 공동 파트에서 **엔티티 잔차 룩업** 기법이 도입돼 큰 이득을 냈습니다.
저는 이 기법을 **독립적으로 검증하고, 확장 가능한 축을 전수 조사**하는 역할을 맡았습니다.

### 1) 독립 재현 — 보고값이 맞는지 확인

보고된 이득이 컸기 때문에, **제 자신의 예측 위에서** 다시 측정했습니다.
평가 연도의 라벨을 어느 경로로도 보지 않는 조합(표는 이전 연도까지만, 계수는 다른 폴드에서 적합)을 구성했습니다.

| | 보고값 | 제 독립 측정 |
| :--- | ---: | ---: |
| 엔티티 잔차 룩업 | +20.2 | **+19.70** |
| 대비 타겟 룩업 | +9.5~11.0 | **+11.00** |

거의 일치했습니다. **이 기법은 진짜였습니다.**

이 검증 과정에서 **누출 진단 기준**도 얻었습니다 — 표가 이미 본 연도에서 계수를 적합하면
계수가 정상의 **10배(0.51 → 4.97)**로 폭주하고 정직한 연도에서 −245가 납니다.
**계수 크기가 예상의 몇 배면 누출을 의심하라**는 규칙을 여기서 만들었습니다.

### 2) 확장 축 18종 — 전부 기각

같은 레시피의 축·타겟을 바꾸면 더 얻을 수 있는지 전수 조사했습니다.
**모든 스윕에 무작위 대조군을 섞어** 위양성 바닥을 함께 측정했습니다.

| 시도 | 후보 | 결과 |
| :--- | ---: | :--- |
| 제3축 교체 (아웃카운트·주자·이닝·리버리지·점수차 등) | 11 | 최고 +0.49 < **대조군 +0.94** |
| 타겟 교체 (복원한 결과 차원들) | 7 | 최고 +1.89 < **대조군 +2.44** |
| 대칭 엔티티 축 | 1 | **누출 오라클조차 +0.06** |
| 게이트·평활 격자 | 20 | 기존 값이 이미 최적, 여지 **+0.00** |

**전부 기각했습니다.** 대조군이 없었으면 두 건은 "발견"으로 보고됐을 것입니다.

이 조사로 **왜 하나의 축만 작동했는지**도 설명할 수 있게 됐습니다 —
그 축은 매치업 성격이라 엔티티 정체성과 안정적으로 상호작용하는 반면,
문맥 변수(아웃·주자·이닝)는 그렇지 않았습니다.
그리고 대칭 축이 죽은 것은 **타겟을 한쪽 엔티티가 통제**하기 때문이었습니다.

### 3) 라이브러리 천장 — 캠페인 중단 판단

가진 모델 57종을 **최적 조합했을 때의 상한**을 계산했습니다.

처음 계산에서 **+113(목표 도달 가능)**이 나왔는데, 앞뒤가 안 맞아 원인을 팠습니다.
일부 모델이 **예측 대상 사건 자체의 실측값**을 쓰고 있었습니다 —
참조 파일의 행 수가 학습 데이터와 정확히 1:1이었습니다. 배포 불가능한 모델이었습니다.

제외하고 다시 계산한 진짜 천장: **+2.1**.

> **어떤 모델의 단독 성능이 주력보다 크게 높으면 그 자체가 경고다.**
> 진짜라면 이미 쓰이고 있었을 것이다.

이 판정으로 **더 뒤져도 목표에 못 간다**는 것이 확정됐고, 남은 시간을 정리에 썼습니다.

학습 스크립트는 `src/gpu_colab/` (5종)에 있습니다.

| 스크립트 | 용도 |
| :--- | :--- |
| `colab_newarm_template.py` | ★ 새 모델 학습 표준 템플릿 — **두 벌 규격을 강제** |

| `colab_arm_c_runner.py` · `colab_super_b_runner.py` | 러너 · 대체 구성 실험 |

### 점수로는 실패했지만, 규율 두 가지를 여기서 얻었습니다

**① 두 벌 규격** — 새 모델은 **판정용**(홀드아웃 기간을 빼고 학습)과
**배포용**(전 기간 학습) 두 벌을 함께 뽑아야 합니다.

배포용만 있으면 홀드아웃 기간이 in-sample이라 단독 성능이 **1982**로 부풀어 보입니다
(정직한 측정값은 730.9). **가치를 잴 수가 없습니다.**
판정용 예측을 확보해 둔 덕분에 **"1년 격차 +33.80 / 2년 격차 +0.00"**이라는
예측 시계 효과를 측정할 수 있었습니다.

**② GPU ≠ CPU** — 같은 하이퍼파라미터·같은 데이터인데 AUC가 **+0.02** 벌어지고
두 예측의 상관이 **0.939**입니다. CPU로 판정하고 GPU로 배포하면
**판정한 것과 다른 물건**을 내는 셈입니다.

### 그리고 가장 큰 교훈

물리 피처 모델에 쓴 T4 시간은 **전량 낭비**였습니다(ρ 0.00%).
그런데 **상한 스크린을 먼저 돌렸으면 몇 분 만에 알 수 있었습니다.**

> **GPU는 "탐색 범위를 넓히는" 도구가 아니라
> "이미 옳다고 판정된 방향을 빨리 실행하는" 도구다.**

이후 규칙을 바꿨습니다 — **GPU를 켜기 전에 `toolkit`의 상한 스크린을 먼저 돌린다.**
상세: `docs/04_GPU_COMPUTE.md`
