## 0. 문제 구조 — 먼저 알아야 손해를 안 본다

### 0.1 채점식

```
skill = 1e5 · (1 − Brier / (r(1−r)))       r = 라벨 평균
```
Brier 는 예측 벡터의 **정확한 2차형식**이다. 이 사실이 아래 모든 것을 가능하게 한다.

### 0.2 블렌드 항등식 (이 대회에서 가장 유용했던 도구)

n 개 arm 을 `Σw=1` 로 섞을 때 블렌드 스킬은 **6개 수치만으로 완전히 결정**된다
(각 arm 의 skill `s_i`, 쌍별 예측거리 `d_ij`):

```
u(w) = wᵀ M w
M_ii = s_i
M_ij = (s_i + s_j)/2 + (1e5 / 2V) · d_ij²        V = r(1−r)
```

**검산 완료**: 실제 arm 5종의 관측 ΔG2 를 이 식이 **최대오차 0.02** 로 재현했다.
→ **arm 을 실제로 섞어보지 않고 종이 위에서 최적 가중치·이득을 계산할 수 있다.**

2-arm 특수형:
```
Δ = (1e5 − s_A) · ρ²        ρ = corr(p_A − y,  p_C − p_A)
```

### 0.3 ⚠️ 이득을 결정하는 것은 ρ 하나다 (실측으로 확인)

세 가지를 실험으로 확인했다:

| 조작 | corr(C,B) | ΔG2 |
| :--- | ---: | ---: |
| 원본 arm | 0.905 | +4.26 |
| 고유방향 **2배** 증폭 | 0.735 | **+4.26** (불변) |
| 고유방향 **3배** 증폭 | 0.583 | **+4.26** (불변) |
| 노이즈 주입 sd 0.02 | 0.838 | **하락** |

**다양성의 "크기" 는 레버가 아니다** — 블렌드가 `w_C` 를 정확히 1/m 로 재조정해 버린다.
**단독 스킬도 레버가 아니다** — 변형 11종에서 `skill ↔ d_AC` 상관 **−0.980**,
단독 최고 모델의 `w_C = 0.000`.
**오직 방향(ρ)만이 이득을 만든다.** "corr 를 낮춰라" 를 목표로 삼으면 노이즈 주입으로
"달성" 되면서 점수가 깎인다 — 지표를 잘못 고르면 최적화가 역효과를 낸다.

→ `src/analysis/armc_projection.py`, `armc_frontier.py`

## 1. 모델 구성 (3-arm + 4단 사후보정)

```
p = (1−W_C)·[w_a·A + (1−w_a)·B] + W_C·C
  → count offset  →  ingame 보정  →  pcxh  →  contrast(ctr)
```

| 구성 | 내용 | 단독 skill(2024) |
| :--- | :--- | ---: |
| **A** | GBDT+MLP 25모델. asof 분해피처, CFA 잠재변수 4개, 게임이론 피처 | 826.7 |
| **B** | CatBoost 20멤버(GPU) + count offset | 845.5 |

빼서 F(2군) 행에 미보정이기 때문 — **arm 별 약점 구간을 가중치로 우회**하는 기법.

## 2. 🏆 최대 성과: 엔티티 잔차 룩업 (pcxh / ctr)

> **[기여 구분]** 이 기법은 **팀 공동 파트에서 도입**됐다.
> 아래는 레시피 정리와, 내가 수행한 **독립 검증(+19.70 재현)·확장 시도 18종(전부 기각)**의 기록이다.
> 담당 파이프라인 기여는 `01_MY_CONTRIBUTION.md` 참조.

**이 대회에서 가장 큰 이득(+23 LB)을 낸 방법.** 다음 대회에서 제일 먼저 시도할 것.

### 2.1 레시피

```
dev_cell = r(투수, cell, 타자손) − r(투수, bucket)
           − [ 리그 r(cell, 타자손) − 리그 r(bucket) ]      ← 이중 중심화
shift    = gate(asof_pitcher_n ≥ n_min) · (β_cell·dev_cell + β_hand·dev_hand)
p ← sigmoid(logit p + shift)
```
`cell = balls*3 + strikes` (0~11), `bucket = sign(strikes − balls)`.
없는 키는 shift 0. 표는 **train 에서만** 적합, 적용은 **행 자신의 키로 조회**.

### 2.2 0 과 +20 을 가르는 5요소 — 하나라도 빠지면 사라진다

1. **이중 중심화** — 엔티티 주효과와 리그 문맥효과를 **둘 다** 뺀다. 순수 상호작용만 남긴다.
2. **제3축** (`batter_hand`) — 2축(투수×카운트)만으로는 **0** 이 나온다. 내가 실제로 0 을 쟀었다.
3. **EB 수축** `K=100` 을 부모 수준(투수×bucket)으로.
4. **관측량 게이트** `asof_pitcher_n ≥ 1000` — 관측 적은 엔티티 배제(적용률 77%).
5. **β 를 다른 폴드에서 적합 + ×0.8 수축** — 폴드내 최적을 그대로 쓰면 안 된다.

### 2.3 검증 (2024 라벨을 어느 경로로도 안 본 조합)

| | 2024 (정직) |
| :--- | ---: |
| pcxh | **+19.70** |
| ctr (위에 추가) | **+11.00** |

LB 환산 ~+25, 실측 LB 차 **+23.3**. 정합.

### 2.4 ⚠️ 어디에나 먹히지는 않는다 (전부 실측)

| 변형 | 결과 |
| :--- | :--- |
| 제3축을 outs/주자/이닝/리버리지/점수차 등 **11종**으로 교체 | 최고 +0.49 < 무작위 대조군 +0.94 ❌ |
| **타자** 대칭축 (batter × cell × pitcher_hand) | 누출 오라클조차 +0.06 ❌ |
| 타겟을 ball/strike/reverse/middle 등 **7종**으로 교체 | 최고 +1.89 < 대조군 +2.44 ❌ |
| `n_min` 5×4 격자 | 출하값 (1000,2000) 이 이미 최적, 여지 +0.00 ❌ |

**`batter_hand` 가 특별했다** — 플래툰은 투수 정체성과 안정적으로 상호작용하는 반면,
문맥 변수(아웃·주자·이닝)는 그렇지 않다. 그리고 타겟이 "제구 성공" 이라 **투수는 통제하고
타자는 통제하지 못한다** — 비대칭이 실재한다.

→ `src/analysis/{axis3_sweep,target_sweep,bcxh_test,joint_v2}.py`, `(표는 팀 공동 파트)`

## 3. 🔓 숨은 라벨 디코딩 (재사용 가치 높음)

주최자가 준 **as-of 누적률** 컬럼에서 **투구별 결과를 복원**할 수 있다.

```
outcome(이번 투구) = rate(다음 행)·n(다음 행) − rate(이번 행)·n(이번 행)
```
연속된 동일 투수 행에서 `n` 이 정확히 1 증가하는 쌍을 쓴다.

**검산**: `success` 차원을 알려진 라벨과 대조 → **99.95% 일치**, 복원률 **99.8%**.
이 방법으로 `reverse / middle / ball / strike` **4개 차원을 추가 확보**했다
(원래는 `control_success` 하나뿐).

**일반 원리**: 누적 통계 컬럼이 있으면 차분해서 원자 이벤트를 복원할 수 있다.
train 안에서만 하면 규정 안전이다.

→ `src/analysis/target_sweep.py` 의 `decode()`

## 4. 검증 방법론 — 이 대회에서 제일 비싸게 배운 부분

### 4.1 폴드 설계

```
≤2021 → 2022 |  ≤2022 → 2023(R행만) |  ≤2023 → 2024
```
- **2023 은 R행만 채점**한다. 2군(F) 리그가 2022→2023 에 레짐 붕괴(`r 0.709→0.473`).
- **2023R 이 LB 최근사 폴드**다 — LB 실측 3건에서 평균절대오차 **3.03** (2024 는 13.72).
  단 **평균 −3.0 낙관 편향**이 있으니 빼고 읽는다.
- ⚠️ **적용 범위를 확인**하라. F행에만 작용하는 상수는 2023R(R행)로 판정할 수 없다.

### 4.2 착수 전 판정기준 확정 (pre-registration)

결과를 보기 **전에** 기준을 로그에 적는다. 이걸 지킨 실험은 전부 정직한 결론이 나왔고,
어긴 실험(v38)은 LB 에서 −4.1 을 냈다.

### 4.3 🎲 무작위 대조군 — 대량 탐색의 필수품

후보가 수백~수천이면 우연히 통과하는 것이 **반드시** 나온다.
**무작위 벡터·무작위 셀분할·셔플한 타겟**을 같은 파이프라인에 통과시켜 **위양성 바닥을 함께 측정**한다.
실제 사용례: 제3축 스윕에서 실후보 최고 +0.49 vs 무작위 최고 **+0.94** → 즉시 기각.

→ `src/experiments/{hunt_rowlocal,hunt_cells}.py`, `src/analysis/axis3_sweep.py`

### 4.4 ρ 스크린 — arm 을 학습하기 **전에** 상한을 잰다

정보원 X 로 **체인 잔차를 직접 회귀**하면, X 위에 세운 어떤 arm 의 기여도 그 값을 못 넘는다.
몇 분이면 끝난다.

실제 결과 (3분할 중첩: 2021+2022 학습 → 2023 계수 → 2024 평가):

| 블록 | ρ |
| :--- | ---: |
| 트랙맨 물리 77피처 | **0.00%** |
| 전체 137피처 | 0.57% |
| test.csv 원본 43 | 0.72% |
| **게이트 통과 필요치** | **1.10%** |

→ 물리 피처로는 원리상 불가능. **GPU 를 쓰기 전에 이걸 돌렸어야 했다.**

→ `src/analysis/rho_screen.py`

### 4.5 시드 규율

**최소 5시드.** 2~3시드는 노이즈를 4~5배 과소평가한다.
v38 실패의 직접 원인: **1폴드 × 1시드**로 판정. 시드만 바꿔도 +6.65 → +3.21 이었다.

### 4.6 새 arm 즉시 판정 게이트

`.npy` 하나(= `train<Y` 학습 → Y 예측)만 있으면 초 단위 판정:
- **G1 다양성** `d_AC ≥ 0.020` 및 `d_BC ≥ 0.020`
- **G2 기여** 최적가중 3-arm − 2-arm > **+12**
- **G3 자유도 방어** 폴드를 반으로 갈라 교차 검증, 둘 다 양수
- ⚠️ **AUC 가 기존 arm 을 크게 웃돌면 누출·특권피처 의심**

→ `src/experiments/gate_newarm.py`

## 5. 규정 준수 검증 (행 독립성)

### 5.1 행동 검증 — 정적 리뷰보다 강하다

프로브 3,000행을 **4변형**으로 파이프라인 전체에 통과시켜 행별 비교:

| 검사 | 잡는 것 | 실측 |
| :--- | :--- | ---: |
| SHUFFLE 불변성 | 행 순서 의존(rolling/shift/정렬) | 0.000e+00 |
| SUBSET 불변성 | 프레임 통계 의존(groupby/평균/분위수) | 4.7e-10 |
| **SOLO 불변성 (1행씩)** | **위 전부 — 가장 강한 검사** | **7.9e-09** |

**1행만 넣어도 3,000행 프레임과 같은 값**이면 프레임 의존이 없다.
진짜 누출은 1e-3 안팎, 부동소수점 잡음은 1e-9 수준이라 명확히 갈린다.

→ `src/analysis/indep_audit.py`

### 5.2 정적 스캔

```bash
find . -name '*.py' -exec grep -nHE \
 '(^|[^a-z_])(te|test|sub|X_test)[a-z_]*\.(groupby|rank\(|rolling|expanding|cumsum|value_counts)' {} +
```
히트가 나오면 **학습 전용 함수 안인지** 확인한다(우리 경우 전부 `fit_tables()` 내부였다).

### 5.3 금지 항목

- **다른 test 행을 참조한 개별 행 보정** (배치 통계, test 내부 target encoding, 순서 rolling)
- **현재 투구의 실측값** — 우리 라이브러리의 `teach_*` arm 3종이 여기 해당한다
  (`PT_feats.pkl` = train 과 1:1, 그 투구의 구속·회전·무브먼트). **배포 자체가 불가능**하고
  규정 위반이다. 단독 skill 이 다른 arm 보다 250 높아 매우 유혹적이니 **스크린에서 항상 제외**할 것.
- 허용: 투수/타자의 **과거** 요약 피처(`asof_*`)는 명시 허용.
